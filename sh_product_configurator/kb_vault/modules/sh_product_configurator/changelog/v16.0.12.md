## [v16.0.12] — Extend duplicate-name-bypass prefix from N-only to N/R
Date: 2026-07-14
Developer: mehkharva (via Claude Code)
Files Touched: models/product_template.py
Why: User requested the existing "N"-prefix duplicate-name/BOM-copy-on-duplicate bypass also apply to names starting with "R", with identical behavior to N — no new logic path, just widen the prefix match.
What Changed: `product.template._should_skip_duplicate_name_validation()` changed from `template_name.upper().startswith('N')` to `template_name.upper().startswith(('N', 'R'))`. Since every consumer (`create()`, `_validate_unique_product_name()` used by both create/write, and `copy()`'s duplicate-flag/variant-skip logic) calls this single method, all of them now treat `R...` names identically to `N...` names with no other code changes required.
KB Files Updated: [[../03_models]], [[../09_known_issues]]
Side Effects: none expected — purely additive prefix match, `N` behavior unchanged. Any product named starting with `R` will now also bypass the duplicate-name check (previously it would have been blocked/validated normally).
